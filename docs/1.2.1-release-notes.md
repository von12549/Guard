# V4 Guards 1.2.1 release notes

V4 Guards 1.2.1 repairs the installed First onboarding flow and completes typed local Profile authoring
on top of the 1.2.0 M1–M5 foundations. The stable public command API remains `1.0`. The release source
and publication evidence are governed by the [1.2.1 release Plan](plans/20261005-v4-guards-1-2-1-release.md).

## Changes since 1.2.0

- The loopback Web Companion shows eight Host-derived onboarding steps and uses preview-bound typed
  actions for discovery, Draft creation, Profile configuration and review-template creation. It reports
  human explanations, machine categories and relative evidence paths without creating acceptance.
- Host onboarding validates the installed package and a fresh hash-only safety proof before roots,
  Target snapshot or discovery can pass. The proof binds the current package, project and Target
  snapshot to persistent User/Machine environment state, Process PATH and four PowerShell profiles.
- `profile configure` validates a separate typed candidate against the Draft, current Target snapshot,
  Module configuration, capabilities, stages and selected rules. `profile review-template` creates a
  deterministic, intentionally incomplete document for human policy and fixture review.
- The installed CLI preserves the stable profile-independent `reset` lifecycle. PATH lookup and the
  host-safety proof use the platform's environment variable spelling on Windows and Linux.
- The compatibility baseline is bound to the 1.2.1 `plugin.json` bytes; its historical
  `pluginVersion=1.1.0` and stable `apiVersion=1.0` are unchanged.

The configured Draft and review template are local candidates. Validation and promotion do not select
a composition, adopt Target `.guard/`, activate CI or remote policy, or authorize IFX P03.

## Assets and prerequisites

The fixed release matrix contains exactly:

| Asset | Deployment | Host prerequisites |
| --- | --- | --- |
| `v4-guards-1.2.1-linux-x64.zip` + `.sha256` | self-contained Linux x64 | PowerShell 7.4+; no shared .NET runtime |
| `v4-guards-1.2.1-win-x64.zip` + `.sha256` | self-contained Windows x64 | PowerShell 7.4+; no shared .NET runtime |

The sole root inside either ZIP is `v4-guards-1.2.1/`. Portable, arm64 and macOS assets are not part of
this release. Each sidecar must match the published ZIP bytes.

## Upgrade and recovery

Install into a new sibling directory with `core/distribution/Install-V4Distribution.ps1` and keep the
receipt outside that directory. Verify the new installation before separately selecting it in a
consumer. Recovery is selection back to the previous verified installation. Verified uninstall requires
the original receipt and an unchanged installed file set. Earlier tags and assets remain immutable.

## Deferred boundaries

This release does not deliver Target governance adoption, composition selection, CI/remote activation,
trusted-CI evidence reuse, remote installation or consumer-specific cutover. The local Workbench and
Profile authoring surfaces remain experimental and non-authoritative.
