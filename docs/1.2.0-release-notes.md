# V4 Guards 1.2.0 release notes

V4 Guards 1.2.0 packages the M1–M5 local foundations and the post-audit security/governance repairs
completed on 2026-10-01. It was published from exact commit
`cf8a9cb631e120309568f18ac965540e381f8027` after Linux-complete, Windows-full, reproducible asset,
candidate/recovery and independent installation gates passed. It is the latest formal release.

## Delivered in 1.2.0

- **M1 self-contained distribution and installed launchers.** The supported assets are self-contained
  `linux-x64` and `win-x64` ZIPs. Launchers derive PackageRoot and the product version from the installed
  package, verify manifest/receipt integrity, refuse drift and do not require `dotnet` on PATH. Linux
  installation restores execute bits only for the two validated native apphosts.
- **M2 Profile authority local foundation.** `profile discover`, `draft`, `validate` and `promote`
  generate non-authoritative candidates and receipts. Promotion packages the reviewed Profile and Module;
  it does not adopt `.guard/`, select a composition or activate CI.
- **M3 local application Workbench foundation.** Typed setup, protection, authority and lifecycle previews
  are available through the Host and loopback-only Companion. They do not apply Target or remote changes.
- **M4 versioned Stage semantics.** v2 dependency/gate/provider/timing behavior and local-advisory evidence
  reuse are isolated from the stable v1 command contract. Local evidence is not trusted CI authority.
- **M5 local governance and Module lifecycle foundations.** Revision-bound Plan sets, exact-diff target
  trust authorization, bound Plan-pair receipts and deterministic Module candidate operations are present.
  Candidates remain non-authoritative until separately reviewed and adopted.

## Audit repairs included

- Candidate adapter execution is limited to explicitly enabled synthetic fixtures. It receives a minimal
  environment, declared timeout and process-tree cleanup; undeclared process/network/write capabilities
  fail closed. This is orchestration confinement, not an OS sandbox.
- Adapter/profile/config/lock/fixture inputs and recursive package entries reject link/reparse/junction
  escapes. External sentinels are neither executed nor copied.
- Target trust validation reads policy, authorization, Plan-set and member bytes from explicit Git
  revisions and verifies member identities, hashes, dependencies, derived union, compositionHash,
  boundaries, protected exact diff and single-use record consumption.
- Finalized Plan pairs use injection-safe Markdown, an exact provenance/hash receipt and same-directory
  staging. Existing evidence is never silently overwritten; tamper, replay and incomplete pairs fail.
- M2–M5 focused suites are part of the protected Linux-complete and Windows-full approved-test lists.

## Assets and prerequisites

The fixed release matrix contains exactly:

| Asset | Deployment | Host prerequisites |
| --- | --- | --- |
| `v4-guards-1.2.0-linux-x64.zip` + `.sha256` | self-contained Linux x64 | PowerShell 7.4+; no shared .NET runtime |
| `v4-guards-1.2.0-win-x64.zip` + `.sha256` | self-contained Windows x64 | PowerShell 7.4+; no shared .NET runtime |

The root inside either ZIP remains `v4-guards-1.2.0/`, so the existing installer and receipt contract are
unchanged. Portable and arm64 assets are not published or certified in this release.

## Upgrade and recovery

Install 1.2.0 into a new sibling directory with `core/distribution/Install-V4Distribution.ps1` and keep
the receipt outside the installation. Do not overwrite a 1.1.x installation. Verify the new installation,
then select it through the consumer's separately governed lifecycle. Recovery is selection back to the
previous verified installation; verified uninstall requires an unchanged file set and receipt.

The stable public API remains `1.0`. The compatibility baseline's historical `pluginVersion` remains
`1.1.0`; only its SHA-256 binding for `plugin.json` changes to the 1.2.0 bytes.

## Still deferred

1.2.0 does not deliver project initialization, Target governance adoption, version-selection/rollback UI,
storage retention, Target `.guard/` adoption, composition selection, CI/remote activation, multi-project
parallel dashboard, trusted-CI evidence reuse, performance/cadence targets, a complete Plan/Module editor,
marketplace/signatures, CODEOWNERS or remote installation. Local candidate, preview and test success do
not claim those outcomes.
