# V4 Guards 1.1.6 release notes

V4 Guards 1.1.6 is the stable base for consumer adoption. It includes:

- the trusted-base authorization for approved-test and runner changes (V4-TODO-014);
- fixes for the two known issues of 1.1.5 (V4-TODO-017 and V4-TODO-018).

The public CLI contract, stable API `1.0`, query contracts, built-in modules and Profiles and the
four-root contract are unchanged. So is the Host and Web Companion source code: their IL is identical to
1.1.5, and only version metadata and the Host debug directory differ.

## Added

- **Trusted-base authorization for protected changes (V4-TODO-014).**
  - The new `integrations/github/trust-policy.json` names the components that the base-owned runner
    `integrations/github/Invoke-V4TrustedBase.ps1` protects: verdict components, certification components
    and every approved test.
  - A change to a protected path needs two pull requests. The first, under an `authorization` Plan, adds a
    single-use record in `docs/plans/authorizations/`. The second, a `trust-change` diff, consumes the
    record with exact base and head SHA-256 values.
  - The new contract `core/contracts/trust-change-authorization.schema.json` defines the record.
  - Every verdict records the hashes of the components that produced it (`verdictComponents` in
    `core/contracts/ci-artifact-manifest.schema.json`).
  - These are repository CI contracts; the Host does not read them.

## Fixed

- **Windows child processes of the trusted-base runner.** The runner's isolated environment now passes
  `PATHEXT`, so Windows children resolve `git` and other commands. Windows smoke checks on pull requests
  depend on this.
- **Long paths in the trusted-base runner (V4-TODO-017).** Every runner Git command now passes
  `core.longpaths=true`, and the isolated target clone persists it. Before, on Windows, a tracked path
  longer than MAX_PATH could read as deleted and fail the HeadRoot or post-test tracked-file check. P6 has
  a regression case for it.
- **Build-location-independent builds (V4-TODO-018).** Independent Release builds of the same commit from
  different directories now produce a byte-identical archive. Before, the Host embedded its absolute PDB
  path, and the Web Companion shipped a static web assets manifest with the absolute source `wwwroot` path.
  - The Host is built without debug information, as the Web Companion already was. Release archives never
    contained a Host PDB.
  - Both projects map the repository root to `/_/`.
  - The Web Companion no longer builds static web assets manifests. As before, it serves its UI only from
    embedded resources.
  - P7 builds a second clone at another location and requires the same archive.

## Changed

- Archive contents (141 entries; 1.1.5 had 140):
  - removed: `companion/v4-web-companion.staticwebassets.runtime.json` and
    `companion/v4-web-companion.staticwebassets.endpoints.json`;
  - added: `package/integrations/github/trust-policy.json`,
    `package/core/contracts/trust-change-authorization.schema.json` and this file.
- The Host PE debug directory contains only the `Reproducible` entry.
- Version metadata: product version `1.1.6`. Host and Web Companion assembly version `1.1.6.0`.

## Compatibility

- Stable API: `1.0`. `core/contracts/cli-contract.json` is unchanged.
- Supported platforms: `linux-x64` and `win-x64`. Prerequisites are unchanged: PowerShell 7.4+ and .NET 10.x.
- Installation, verified uninstall and offline bundle composition work as in 1.1.5. Install 1.1.6 as a new
  sibling installation. 1.1.5 and earlier releases stay immutable.
- Schema `$id` values keep their historical `https://ifx.local/v4/...` namespace.

## Known issues

None carried over from 1.1.5.
