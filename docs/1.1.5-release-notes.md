# V4 Guards 1.1.5 release notes

V4 Guards 1.1.5 is the first release published from the standalone repository `von12549/Guard`. It follows
the history-preserving extraction of V4 from the IFX incubation repository (V4-TODO-008). The release is
intended as the standalone source authority. It **changes no runtime behavior** compared with 1.1.4.

## Provenance

- Source history is extracted from IFX `docs/guards/v4` at `80f7b6b65fb06897444a6a36c604c42c93c834e4`,
  which includes the published 1.1.4 lineage. The commit map and records are in `docs/migration/v4-todo-008/`.
- Releases 1.0.0 through 1.1.4 were published from `von12549/IFX` and remain immutable at their original
  release URLs. They are not re-tagged here.
- Host and Web Companion built from this source are byte-identical to builds from the IFX-certified 1.1.4
  source once build-location inputs are normalized, apart from version metadata.

## Changed

- **Standalone layout.** PackageRoot is the repository root. Repository governance (`docs/plans/**`,
  `docs/migration/**`) is excluded from package authority, so it never enters the package or the archive.
- **Tests.** Tests write mutable data to an external work root (`<TEMP>/v4-guards-work/...`) and no longer
  assume an enclosing IFX checkout.
- **Certification and trusted-base runner.** Both use standalone paths, and trusted-base Plan discovery
  reads `docs/plans/*.plan.json`.
- **Inactive workflow specimen.** It now targets `main` and prefetches only base-locked NuGet dependencies
  with SHA-512 verification. The dormant-state checks accept an active `.github/workflows/v4-guards.yml`
  only when it matches the reviewed specimen except for its first comment line.
- **Version metadata.** Product version `1.1.5`. Host and Web Companion assembly version `1.1.5.0`.

## Compatibility

- Stable API: `1.0`. The public CLI, query and schema contracts, built-in modules and profiles, and the
  four-root contract are unchanged.
- Supported platforms: `linux-x64` and `win-x64`. Prerequisites are unchanged: PowerShell 7.4+ and .NET 10.x.
- Schema `$id` values keep their historical `https://ifx.local/v4/...` namespace.

## Known issues (unchanged from 1.1.4)

- The trusted-base runner's post-test `git status` on the isolated target does not pass
  `core.longpaths`. On Windows, very deep Target paths below a long root can report a false modification.
  Workaround: run from a short root.
- Host and Web Companion builds made in different locations are not byte-identical, because they embed the
  build-location PDB path and the static web assets content root. Archives are byte-identical for the same
  Host and Companion input.
